# HRV 分析与情绪/睡眠/疲劳/压力评估 —— 工作计划

> 建立日期：2026-09-08
> 说明：这是后续工作的路线图。每做完一个阶段就把前面的 `[ ]` 改成 `[x]`，方便跟踪进度。

## 一句话目标

把设备从「只能测心率」，升级成「能看出一个人当前的放松程度、紧张程度、疲劳程度、压力水平、睡眠恢复情况」。

---

## 一、大白话背景（为什么要做这些）

- 现在设备已经能采到心电信号，并算出一个**平均心率**。
- 但「平均心率」只是一个数字，信息很有限。同一个人，心率都是 70，可能很放松，也可能很紧张——光看心率分不出来。
- 真正能反映情绪、压力、疲劳、睡眠的，是**心率变异性（HRV）**：也就是**每一次心跳之间时间间隔的细微变化**。
  - 变化丰富、灵活 → 身体状态好、放松、恢复能力强；
  - 变化僵硬、呆板 → 紧张、疲劳、压力大。
- 这个「变化」在数学上可以拆成不同频率的「波段」，每个波段对应身体不同的调节机制。就像把一束白光拆成彩虹，不同颜色代表不同信息——这就是**频域分析**，也是和情绪/压力/睡眠直接挂钩的部分。

---

## 二、先统一几个概念（避免后面混淆）

### 1. 心率 vs 心率变异性（HRV）

| 概念 | 是什么 | 通俗说法 |
|---|---|---|
| 心率 | 每分钟跳几次 | 心跳「快不快」 |
| HRV | 每次心跳之间间隔差多少 | 心跳「灵活不灵活」 |

两者是两回事。同样 70 的心率，HRV 可能高（放松）也可能低（疲劳）。

### 2. 时域 vs 频域

- **时域**：直接看「心跳间隔」这串数字本身（比如它们的标准差）。
- **频域**：把这串间隔的「变化」拆成不同频率来看，得到几个波段的能量。

### 3. 频域的三个主要波段（后面分析的重点）

| 波段 | 频率范围 | 主要反映 | 通俗说法 |
|---|---|---|---|
| VLF 极低频 | 0.003–0.04 Hz | 体温、内分泌等慢调节 | 短时评估一般不作为重点 |
| LF 低频 | 0.04–0.15 Hz | 交感+副交感共同作用、血压调节 | 「身体的动员程度」 |
| HF 高频 | 0.15–0.4 Hz | 副交感（迷走神经）、与呼吸有关 | 「放松与恢复能力」 |
| LF/HF 比值 | — | 交感/副交感的平衡 | 「紧张 vs 放松的天平」 |
| TP 总功率 | ≤0.4 Hz | 整体调节能力 | 「整体的活力储备」 |

> 一句话记忆：**HF 高 = 放松、恢复好；LF/HF 高 = 紧张、有压力。**

### 4. 一个容易搞混的地方：两种「频谱」不是一回事

- **现有代码里的频谱（spectrum.c）**：是对**原始心电波形**做频谱，用来查信号里有没有噪声、滤波是否干净。这是「信号质量」工具，不是「生理分析」。
- **本次计划要做的频谱（阶段三）**：是对**心跳间隔序列（RR 间期）**做频谱，得到 LF/HF 等波段。这才是和情绪/压力挂钩的「生理分析」。

两者名字都叫「频谱」，但输入的东西和目的完全不同，后面会反复用到这个区别。

## 三、现状盘点（我们已经有什么）

| 已有能力 | 位置 | 状态 |
|---|---|---|
| 采集心电信号（KS1092 + ESP32-S3，500Hz） | main/main.c、myspi.c | 可用 |
| 简单平均心率（斜率法） | main/heart_rate.c | 可用，但精度对 HRV 可能不够 |
| 软件滤波（IIR / 卡尔曼） | main/iir_filter.c、kalman_filter.c 等 | 可用 |
| 诊断用频谱（查噪声） | main/spectrum.c | 可用，但非生理频域分析 |
| BLE 上传数据 | main/ble.c | 可用 |

**结论**：信号采集和传输的「地基」已经有了，缺的是上面的「HRV + 频域 + 状态解读」这栋楼。

## 四、分阶段工作计划

### 阶段一：把每一次心跳的时间点找准（R 波定位 + RR 间期提取）

- **目标**：从原始心电波形里，准确找出每一次心跳发生的时刻，算出相邻两次心跳的时间间隔（称为 RR 间期，单位毫秒）。
- **为什么**：HRV 的一切都建立在准确的 RR 间期上。心跳时间点找不准，后面所有指标都是错的。
- **要做的事**：
  - 评估现有 `heart_rate.c` 的斜率法精度是否够用（大概率不够，需要换更稳健的「QRS 波检测」，比如阈值 + 不应期，或 Pan-Tompkins 类方法）。
  - 输出一串连续的 RR 间期。
- **验收标准**：拿一段已知心跳次数的信号，人工数一遍，和算法结果对得上（误差应很小）。

### 阶段二：HRV 时域分析

- **目标**：算出一组「时域指标」。
- **为什么**：这些是 HRV 最基础、最成熟的指标，也是后面频域分析的输入。
- **要算的指标**：

| 指标 | 含义 | 通俗说法 |
|---|---|---|
| SDNN | 所有 RR 间隔的标准差 | 整体 HRV 高低 |
| RMSSD | 相邻 RR 差值的均方根 | 副交感 / 放松能力 |
| pNN50 | 相邻 RR 差 >50ms 的比例 | 副交感 / 放松能力 |
| 平均心率 / 平均 RR | 基础心率 | 心跳快慢 |

- **验收标准**：能稳定输出这几个数字。

### 阶段三：HRV 频域分析（这才是「频谱分析」的重点）

- **目标**：把 RR 间期序列做频域变换，得到 LF、HF、VLF、LF/HF、总功率。
- **为什么**：频域才是和情绪/压力/睡眠直接挂钩的部分。
- **技术要点（大白话）**：
  - 心跳间隔不是等时间采样的，需要先「插值/重采样」成均匀的时间序列，再做 FFT；或用 Lomb-Scargle 方法直接处理非均匀数据。
  - 建议用 2–5 分钟的窗口（标准短时 HRV 是 5 分钟）。
- **验收标准**：得到 LF/HF 等数值；对一段已知「放松」和一段已知「紧张」的数据，能看出明显差异。

### 阶段四：把频段指标翻译成「身体状态」

- **目标**：整理一份「指标 ↔ 生理含义 ↔ 通俗解读」的对照表，把数字翻译成人话。
- **为什么**：数字本身没用，用户要看懂才有意义。
- **参考对照**（见下方第五节，先给出一份初版）。
- **验收标准**：拿出一份清晰的对照文档，任何一个非技术的人能看懂「LF/HF 高」意味着什么。

### 阶段五：映射到情绪 / 睡眠 / 疲劳 / 压力

- **目标**：建立「指标 → 结论」的规则，输出一段用户能看懂的报告（例如：当前压力偏高、偏疲劳、建议休息）。
- **要覆盖的四个方面**（趋势性参考，非医疗诊断）：

| 状态 | 典型指标变化（趋势） | 通俗解读 |
|---|---|---|
| 放松 / 平静 | HF 高、LF/HF 低、RMSSD 高 | 副交感主导，恢复好 |
| 压力 / 紧张 | LF/HF 高、HF 低 | 交感主导，身体在「备战」 |
| 疲劳（身心） | SDNN、总功率、HF 整体下降 | 调节能力变弱，身体「没电」 |
| 睡眠恢复好 | 夜间 HF 高、HRV 高 | 深度休息、恢复好 |
| 睡眠恢复差 | 整体 HRV 偏低 | 恢复不足 |

- **验收标准**：对同一组数据，能自动输出一段人话报告。

### 阶段六：落地到设备和上位机（视后续需求定）

- **目标**：决定「在设备端实时算」还是「数据传到电脑/App 再算」，并做出展示。
- **要考虑的点**：
  - ESP32 的算力和内存有限，长时 HRV 可能更适合传到上位机算。
  - 睡眠分析需要整晚长时间记录，和几分钟的短时测量是两套做法。
- **验收标准**：跑通「采集 → 计算 → 展示」的完整闭环。

## 五、频段含义速查表（阶段四的初版参考）

| 指标 | 升高意味着 | 降低意味着 |
|---|---|---|
| SDNN | 整体调节能力好 | 整体调节能力差、疲劳 |
| RMSSD / pNN50 | 副交感活跃、放松 | 副交感弱、恢复差 |
| HF | 放松、恢复能力强 | 紧张、恢复差 |
| LF | 交感/副交感动员程度高 | 动员程度低 |
| LF/HF | 偏紧张、有压力 | 偏放松、平静 |
| 总功率 TP | 活力储备足 | 活力储备不足、疲劳 |

> 重要提醒：以上都是「人群统计上的趋势」，不是「对某个人 100% 成立的诊断」。每个人的基础值不同，做评估时应先建立这个人的「基线」，再看相对变化。这些结论只能作为「参考性健康提示」，不能当医疗诊断。

## 六、需要你先拍板的几个问题（不着急，想清楚再定）

1. **用途**：是想「短时测量」（几分钟测一次，看当下压力/疲劳），还是「长时间监测」（比如整晚测睡眠）？—— 这决定窗口长度和是否做睡眠分期。
2. **算在哪里**：在设备（ESP32）上实时算，还是把数据传到电脑/App 再算？—— 这决定整体架构。
3. **面向谁**：是自己研究验证，还是要做成产品给别人用？—— 这决定报告要多通俗、界面要多友好。
4. **要不要「给建议」**：是只出指标数字，还是希望系统顺带给出「建议休息」之类的人话建议？

## 七、风险与注意事项

1. **R 波检测精度是命根子**：阶段一没做好，后面全白做。这一块要花最多时间反复验证。
2. **采样时间精度**：HRV 对「每次心跳的时间戳」精度敏感。BLE 分包传输可能引入时间抖动，必要时需要在设备本地打高精度时间戳。
3. **个体差异**：不要用一套固定阈值硬套所有人，先做基线。
4. **运动伪影 / 脱落**：运动或电极脱落会让信号变脏，导致 HRV 算错，需要先做信号质量判断，脏数据不算或标出来。
