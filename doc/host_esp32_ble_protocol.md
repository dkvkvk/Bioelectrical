# 上位机与 ESP32 BLE 通信协议说明

本文档说明上位机与 ESP32-S3 固件之间的 BLE 数据交互。协议分为两部分：

- 上位机 -> ESP32：6 字节控制命令，用于设置 KS1082/KS1092 增益、采样率、滤波开关和设备开关。
- ESP32 -> 上位机：23 字节数据帧，通过 BLE Notify 回传电量、CH1/CH2 采样数据、脱落检测和平均心率。

相关代码：

- BLE 服务与数据发送：`main/ble.c`
- 命令解析、采样、滤波：`main/main.c`
- KS1082/KS1092 SPI 寄存器写入：`main/KS1092.c`

## 1. BLE 服务与特征

设备名：

```text
BLE_EEG
```

UUID 规则沿用 nRF52832 上位机协议：

| 用途 | 16-bit UUID | 128-bit UUID | 方向 |
|---|---:|---|---|
| Service | `0x000A` | `8653000a-43e6-47b7-9cb0-5fc21d4ae340` | - |
| Data / TX | `0x000B` | `8653000b-43e6-47b7-9cb0-5fc21d4ae340` | ESP32 Notify 给上位机 |
| Command / RX | `0x000C` | `8653000c-43e6-47b7-9cb0-5fc21d4ae340` | 上位机 Write 给 ESP32 |

上位机需要：

1. 连接 `BLE_EEG`。
2. 订阅 Data 特征 `0x000B` 的 Notify。
3. 向 Command 特征 `0x000C` 写入 6 字节命令。

## 2. 上位机 -> ESP32 命令格式

命令长度固定为 6 字节。ESP32 收到长度不是 6 的命令会打印警告并忽略。

```text
byte0 byte1 byte2 byte3 byte4 byte5
CH1   CH2   SR    F1    F2    SW
```

| 字节 | 名称 | 含义 | 当前处理 |
|---:|---|---|---|
| `byte0` | `CH1SET` | CH1 通道配置 | 写入 KS1082/KS1092 `CH1SET` 寄存器 |
| `byte1` | `CH2SET` | CH2 通道配置 | 写入 KS1082/KS1092 `CH2SET` 寄存器 |
| `byte2` | `SR` | 采样率设置 | ESP32 重启采样定时器，不写入芯片寄存器 |
| `byte3` | `F1` | CH1 数字滤波开关 | `0x00=关闭`，非 0 开启 |
| `byte4` | `F2` | CH2 数字滤波开关 | `0x00=关闭`，非 0 开启 |
| `byte5` | `SW` | 设备发送开关 | `0x00=停止 BLE 发包`，非 0 开始发包 |

### 2.1 CH1/CH2 增益配置

`CH1SET` 和 `CH2SET` 是直接写入 KS1082/KS1092 芯片的寄存器值。放大由模块内部模拟前端完成，ESP32 只是通过 SPI 写配置，再用 ADC 采集模块输出的 `VO1/VO2`。

当前默认上电配置：

```text
CH1SET = 0x20
CH2SET = 0x00
```

初始化流程参考 nRF52832：写一次默认配置，等待 500 ms，再写一次相同配置。

常用配置：

| 增益 | CH1SET | CH2SET |
|---:|---:|---:|
| `360x` | `0x20` | `0x00` |
| `540x` | `0x30` | `0x10` |
| `720x` | `0x34` | `0x14` |
| `1080x` | `0x38` | `0x18` |
| `1440x` | `0x3C` | `0x1C` |
| `680x` | `0x22` | `0x02` |
| `1020x` | `0x32` | `0x12` |
| `1360x` | `0x36` | `0x16` |
| `2040x` | `0x3A` | `0x1A` |
| `2720x` | `0x3E` | `0x1E` |

注意：高增益不一定让上位机波形更好。如果电极直流偏置、接触噪声或输入幅度较大，`1080x` 以上可能让前端或 ADC 出现饱和，表现为削顶、贴边、跳变或波形混乱。

### 2.2 采样率字段

采样率字段只控制 ESP32 采样定时器，不写入 KS1082/KS1092 寄存器。

| `SR` 值 | 采样率 | 定时器周期 |
|---:|---:|---:|
| `0x04` | `250Hz` | `4000us` |
| `0x02` | `500Hz` | `2000us` |
| `0x01` | `1000Hz` | `1000us` |
| 其他 | `500Hz` | `2000us` |

当前数字滤波器按 `500Hz` 采样设计。若使用 `1000Hz` 且开启滤波，波形可能变形或看起来像削波。调试原始波形时建议先使用 `500Hz` 并关闭滤波。

### 2.3 滤波开关

`F1/F2` 控制 ESP32 侧的软件数字滤波：

| 字段 | `0x00` | 非 `0x00` |
|---|---|---|
| `F1` | CH1 不滤波，直接使用 ADC 电压 | CH1 开启软件滤波 |
| `F2` | CH2 不滤波，直接使用 ADC 电压 | CH2 开启软件滤波 |

关闭滤波时，数据值约为：

```text
ADC电压(V) * 10000
```

开启滤波时，数据值来自当前软件滤波输出，并加回约 `0.9V` 的显示偏置后再乘以 `10000`。

### 2.4 设备开关

`SW=0x00` 时，ESP32 仍然采样和处理数据，但不通过 BLE Notify 发送数据帧。

`SW!=0x00` 时，ESP32 正常发送数据帧。

## 3. 命令示例

默认低增益、500Hz、开启双通道滤波、开始发包：

```text
20 00 02 01 01 01
```

默认低增益、500Hz、关闭双通道滤波、开始发包：

```text
20 00 02 00 00 01
```

1080x 增益、500Hz、开启双通道滤波、开始发包：

```text
38 18 02 01 01 01
```

默认低增益、250Hz、开启双通道滤波、开始发包：

```text
20 00 04 01 01 01
```

默认低增益、1000Hz、关闭双通道滤波、开始发包：

```text
20 00 01 00 00 01
```

```text
20 00 02 01 01 00
```

## 4. ESP32 -> 上位机数据帧

ESP32 通过 Data 特征 `0x000B` Notify 固定发送 23 字节数据帧。

```text
FF 17 2E
+ battery(1)
+ CH1(2) CH2(2)
+ CH1(2) CH2(2)
+ CH1(2) CH2(2)
+ CH1(2) CH2(2)
+ lead_off(1)
+ heart_rate(1)
+ crc8(1)
```

字段表：

| 下标 | 长度 | 含义 |
|---:|---:|---|
| `0` | 1 | 帧头 `0xFF` |
| `1` | 1 | 帧长度/协议字段 `0x17` |
| `2` | 1 | 数据类型 `0x2E` |
| `3` | 1 | 电量百分比，范围约 `1-100` |
| `4-5` | 2 | 第 1 组 CH1 数据，高字节在前 |
| `6-7` | 2 | 第 1 组 CH2 数据，高字节在前 |
| `8-9` | 2 | 第 2 组 CH1 数据，高字节在前 |
| `10-11` | 2 | 第 2 组 CH2 数据，高字节在前 |
| `12-13` | 2 | 第 3 组 CH1 数据，高字节在前 |
| `14-15` | 2 | 第 3 组 CH2 数据，高字节在前 |
| `16-17` | 2 | 第 4 组 CH1 数据，高字节在前 |
| `18-19` | 2 | 第 4 组 CH2 数据，高字节在前 |
| `20` | 1 | 脱落检测 |
| `21` | 1 | 平均心率 |
| `22` | 1 | CRC-8 |

CH1/CH2 数据解析：

```c
uint16_t ch1 = ((uint16_t)buf[index] << 8) | buf[index + 1];
uint16_t ch2 = ((uint16_t)buf[index + 2] << 8) | buf[index + 3];
```

ESP32 每采集 4 个点发送 1 帧。因此 BLE Notify 帧率约为：

| 采样率 | 每帧点数 | Notify 帧率 |
|---:|---:|---:|
| `250Hz` | 4 | `62.5 帧/s` |
| `500Hz` | 4 | `125 帧/s` |
| `1000Hz` | 4 | `250 帧/s` |

`1000Hz` 时 BLE Notify 压力较高，上位机绘图或 BLE 链路如果处理不过来，可能出现丢帧、显示断裂或波形异常。

## 5. CRC-8

CRC 位于 `buf[22]`，计算范围为前 22 字节：

```text
crc = CRC8(init=0x00, data=buf[0..21])
buf[22] = crc
```

固件使用查表法，表在 `main/ble.c` 的 `crc8_table`。上位机只要和该表/算法一致即可。

伪代码：

```c
uint8_t crc8(uint8_t crc, const uint8_t *buffer, int size)
{
    while (size--) {
        crc = crc ^ *buffer++;
        crc = crc8_table[crc & 0xFF];
    }
    return crc;
}
```

## 6. 调试日志对照

收到命令时，ESP32 会打印：

```text
BLE RX raw (6 bytes):
20 00 02 01 01 01

CMD: CH1=0x20 CH2=0x00 SR=2 F1=1 F2=1 SW=1
CMD decode: CH1SET=0x20 (...360x), CH2SET=0x00 (...360x), SR=500Hz, CH1 filter=ON, CH2 filter=ON, device=ON
CMD applied: CH1SET=0x20, CH2SET=0x00
Sample timer restarted: 2000 us interval (500 Hz), device=ON, filter1=ON, filter2=ON
```

采样调试日志：

```text
ADC debug: raw1=... mv1=... raw2=... mv2=... ch1set=0x20 ch2set=0x00 filt1=... filt2=... device=ON
```

其中：

- `raw1/raw2` 是 ESP32 ADC 原始值。
- `mv1/mv2` 是 ADC 校准后的毫伏值。
- `ch1set/ch2set` 是固件最后一次确认写入的寄存器配置值。
- `filt1/filt2` 是准备进入 BLE 数据帧的滤波/非滤波电压值。

## 7. 推荐联调顺序

1. 先发 `20 00 02 00 00 01`，用 `360x + 500Hz + 关闭滤波` 看原始波形。
2. 原始波形正常后，再发 `20 00 02 01 01 01` 打开滤波。
3. 需要更大幅度时，再测试 `38 18 02 00 00 01`，先关闭滤波确认是否饱和。
4. 1000Hz 调试建议先关闭滤波：`20 00 01 00 00 01`。
5. 如果命令日志正常但波形不变，优先检查 SPI 写寄存器、KS1082/KS1092 模块供电、VO1/VO2 到 GPIO1/GPIO2 的连接。


## 8. 命令重复抑制与按通道选择性应用（2026-09-15 固件更新）

为消除"修改配置导致波形抖动"的问题，固件对命令处理做了两级优化：

### 8.1 完全相同的命令直接忽略

上位机发来的 6 字节命令若与设备当前配置**逐字段完全一致**（增益、采样率、
两通道滤波、数据开关都相同），固件只记一条日志直接忽略，不触发任何重置。
上位机侧同样做了拦截：连续点击「应用设置」但配置没变时，命令根本不会发出
（该行为不依赖新固件，旧固件也能受益）。

### 8.2 有变化的命令按需选择性重置

命令确实有变化时，设备只重置受影响的部分：

| 变化项 | 设备动作 |
|---|---|
| 某通道的增益或滤波开关变化 | 只重置**该通道**的滤波器（另一通道波形不受影响） |
| 采样率变化 | 重启采样定时器 + 重置两通道滤波器（滤波系数与采样率相关） |
| 只有数据开关(SW)变化 | 不重置任何滤波器，不重启定时器 |
| 增益未变化 | 不重写 SPI 寄存器 |

效果：只改通道1的滤波时，通道2的波形完全连续无抖动；采样率不变时连
采样都不会中断（当拍继续采样，无断点）。

注意：此优化需要**重新烧录固件**后生效（ESP-IDF 版 `main/main.c` 与
Zephyr 版 `zephyr_port/src/main.c` 已同步修改）。
